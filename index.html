Redex Workbench

Lean decides that two terms are equal by rewriting them until they match. Each kind of rewrite has a Greek letter, and each one replaces a term with another that means the same thing. This page lets you fire them by hand.

Workbench

A redex is a part of a term that a rule can rewrite. Pick a rule or an example to load it into the workbench. Each example’s thumbnail is its whole reduction graph in miniature (section 2).

Each box is one piece of syntax: a λ box with its binder on a tab, an application box with the function first and its arguments after it, a pair box. A variable is a tag in the color of the binder it belongs to, and the arcs above link each one to that binder.

A badge on a box’s corner marks a redex. Hover it to see the rule match: the rule’s pattern variables and the pieces of the term they stand for get the same highlighter color. Click it and each piece moves to where the result uses it. Step fires the leftmost-outermost redex, To WHNF reduces only the head, and Normalize runs until no redex is left.

Every path

A term with several redexes can reduce in several orders. The graph shows all of them at once. When two paths split, they can always be joined again (the Church–Rosser theorem), so a term has at most one normal form.

Each row is a number of steps from the start. A circle is a term that can still reduce at its head, a diamond is in weak head normal form, and a filled square is a normal form. The number beside a mark is the term’s size. Hover a mark to read the term, and pick a route to see which path a strategy takes.

Strategies

A strategy is a rule for choosing the next redex. Normal order finds the normal form whenever one exists. Applicative order evaluates arguments first, which saves work when an argument is used many times and loops when a looping argument is never used.

Every term is a head applied to zero or more arguments: in f a b the head is f. A term is in weak head normal form when no rule can change its head: the head is a variable (a ((λy. y) a)), a constructor (succ (…), (…, …)), or a λ with no arguments (λx. …). The arguments and the inside of the λ may still hold redexes. That is enough to answer “what shape is this term?”, which is all Lean’s whnf asks before it compares two heads or picks a branch of a recursor.

In Lean 4

αNothing to do
Bound variables are de Bruijn indices (Expr.bvar), so α-equivalent terms are the same Expr. Binder names are kept only for display. The workbench’s “de Bruijn” toggle shows this.
βAlways on
Every definitional equality check and dsimp uses it. Force it with beta_reduce (Mathlib). simp flag beta.
ηUsed to compare, never to compute
rfl proves (fun x => f x) = f and p = (p.1, p.2). simp flags eta and etaStruct. Mathlib: eta_reduce.
δControlled by transparency
unfold f, delta f, simp [f]. The attributes @[reducible] and @[irreducible] decide what unfolds automatically.
ζInline a let
simp flag zeta. zetaDelta also unfolds let-bound hypotheses x : α := v. intro x moves a let into the context.
ιComputation
rfl and decide run on it. simp flag iota. It gets stuck on well-founded recursion; use unfold f or f.eq_def there.
πProjections
Expr.proj reduces when its argument is a constructor application. simp flag proj. Coq counts this as part of ι.
⇥WHNF and full normal form
whnf (Mathlib tactic) reduces the head only, like the third strategy lane. #reduce t prints the full normal form.

Lean’s kernel also has rules this page does not model: Quot.lift f h (Quot.mk r a) ⟶ f a, K-like reduction of Eq.rec, GMP arithmetic on Nat literals, proof irrelevance, and η for unit-like structures.
